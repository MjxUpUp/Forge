# Rust 代码审查清单

## 正确性

- [ ] 逻辑覆盖所有分支（match 穷举、if/else 覆盖边界情况）
- [ ] 错误处理：无对重要 Result 的静默 `let _ = ...`
- [ ] 数值运算：在适用处检查溢出
- [ ] 字符串处理：对外部输入的 UTF-8 转换不使用 `.unwrap()`
- [ ] 边界检查：数组/切片访问前已验证索引

## 安全性

- [ ] 对用户控制的输入不使用 `unwrap()` / `expect()`
- [ ] `unsafe` 块有 `// SAFETY:` 注释解释安全性
- [ ] 无硬编码的密钥、API Key 或凭证
- [ ] 所有公开 API 边界有输入验证
- [ ] 文件路径已消毒（无路径穿越：`../`）
- [ ] SQL/命令注入不可能（参数化查询，不用 `format!` 拼接命令）

## 异步 Rust

- [ ] 无跨 `.await` 点持有的 `MutexGuard`（死锁风险）
- [ ] 所有 `.await` 都存在（缺失 `.await` = Future 永远不被 poll）
- [ ] spawn 的任务被追踪并在关闭时取消
- [ ] Channel 容量有界（无界 = 高负载时 OOM）
- [ ] 异步上下文中无阻塞调用（`std::thread::sleep`、同步 I/O）
- [ ] `tokio::select!` 分支正确处理取消

## 性能

- [ ] 无不必要的大数据结构克隆
- [ ] 共享所有权使用 `Arc` 而非 `Clone`
- [ ] 热路径中最小化分配（用 `with_capacity` 预分配 `Vec`）
- [ ] 无 O(n²) 算法（存在 O(n log n) 或 O(n) 替代时）
- [ ] 数据库/网络调用不在循环中（应批量处理）

## API 设计

- [ ] 公开函数有文档注释
- [ ] 类型可见性适当（`pub` vs `pub(crate)` vs 私有）
- [ ] 错误类型描述性强且使用 `thiserror`
- [ ] 多字段结构体使用 Builder 模式或 Default
- [ ] 使用 `impl From<X>` 而非手动转换函数

## 测试

- [ ] 每个公开方法至少一个测试
- [ ] 边界情况已测试：空输入、边界值、错误路径
- [ ] 异步测试使用 `#[tokio::test]`
- [ ] 测试相互独立（无共享可变状态）
- [ ] 测试名描述被测行为，而非方法名
- [ ] 测试中无遗留的 `println!` 调试——使用 `tracing` 或断言

## 代码组织

- [ ] 文件不超过 500 行（超过则拆分）
- [ ] 模块间无循环依赖
- [ ] 相关类型在同一模块中
- [ ] `mod.rs` 只做重导出，不含逻辑
- [ ] 命名一致：函数 `snake_case`，类型 `CamelCase`
