# Skill 质量评分 Rubric（四维，总分 100）

借鉴 grafana/skills 的四维评分法。与 R1-R17 机器校验**分工**：R1-R17 管机器判得了的格式
与结构（字段白名单、行数、description 必含段、evals schema），本 rubric 管机器判不了的
质量维度——评审（人工或 LLM）时逐维打分。

**合并阻断线：总分 < 75 不予合并**；任一维度 ≤ 10 也视为阻断（短板效应）。

## 评分流程

1. 先跑 `forge skills validate` + `forge skills audit`（R1-R17 + 安全规则），机器能拦的不占
   人工评审带宽。
2. 评审人（或 LLM 评审子代理）按下表四维各打 0-25 分，对照锚点判据给分，给不出锚点对应
   的具体证据就往下取档。
3. 四维相加得总分，对照阻断线裁决。

## 维度 1：简洁性 conciseness（0-25）

行数预算与 token 效率。skill 是要注入上下文的，每个 token 都有成本。

| 档位 | 判据示例 |
|------|----------|
| 0 | SKILL.md 超 500 行硬上限且无 references 拆分；或正文大段重复 references 已有内容 |
| 10 | 行数合规但有明显冗余：同一原则在 3 处以上重复表述；示例超过 2 个且互相无增量信息 |
| 20 | 基本精炼，仅个别段落可压缩；频繁加载型 skill 正文已压到 200 词附近 |
| 25 | 每段都有信息增量；详细内容全部下沉 references，正文只做路由与核心规则；getting-started 类 <150 词 |

## 维度 2：可操作性 actionability（0-25）

给具体命令和检查清单，不给说教。读者拿到就能执行，不用自己翻译原则。

| 档位 | 判据示例 |
|------|----------|
| 0 | 通篇原则性描述（"要注意质量""应当谨慎"），全文找不到一条可直接复制的命令或检查项 |
| 10 | 有少量命令但关键路径缺失：如要求"验证通过"却不给验证命令；checklist 项无法判断勾选与否 |
| 20 | 主流程每步有命令或明确判据，少数分支场景仍停留在描述层 |
| 25 | 每个「应当/必须」都能对应到命令、清单项或可观察判据；gotcha 含 问题/现象/解决 三要素 |

## 维度 3：工作流清晰度 workflow clarity（0-25）

步骤、门控、退出条件明确。读者知道自己在哪一步、下一步是什么、什么时候算完。

| 档位 | 判据示例 |
|------|----------|
| 0 | 步骤顺序不明或自相矛盾；无退出条件，读者不知道何时停止 |
| 10 | 有步骤列表但无门控：失败时怎么办、能否跳过、什么算通过都没写 |
| 20 | 主流程有步骤+门控，退出条件明确；少数异常路径（回退/中止）未覆盖 |
| 25 | 步骤严格有序，每步有进入/通过判据；含失败处置（决策树或 revert 路径）与明确完成定义 |

## 维度 4：渐进披露 progressive disclosure（0-25）

分层加载：metadata → SKILL.md body → references，每层只放该层的内容。

| 档位 | 判据示例 |
|------|----------|
| 0 | 全部内容堆在 SKILL.md；或 references 套了子目录（违反 R11）；正文塞满一次才用得上的细节 |
| 10 | 有 references 拆分但切分不合理：正文与 references 职责重叠，或正文超过 200 行目标仍无拆分 |
| 20 | 正文 ≤200 行目标基本达成，references 按主题分层；仅个别大块引用缺 ToC |
| 25 | 正文精炼只做路由+核心规则；references 单一职责；>300 行的 reference 文件带 ToC；交叉引用用「详见 references/xxx.md」而非复制 |

## 总分裁决

| 总分 | 裁决 |
|------|------|
| 90-100 | 可直接合并 |
| 75-89 | 可合并，建议记录可改进点 |
| 60-74 | **阻断**（<75），指明最低分维度返修后重评 |
| <60 | 阻断且需结构性重写，建议先对照 SKILL.md 正文规范重做 |
| 任一维 ≤10 | 无论总分，阻断 |

## 与 R1-R17 的分工

| 机制 | 管什么 | 谁来执行 |
|------|--------|----------|
| R1-R17（`forge skills validate`） | 格式与结构硬约束：frontmatter 字段、行数、description 必含 Use when/SKIP、references 层级、evals schema | 机器，每次改动后必跑 |
| 21 条安全规则（`forge skills audit`） | 安全问题（curl\|sh、凭证明文等） | 机器，每次改动后必跑 |
| 本 rubric | 机器判不了的质量：是否精炼、是否可执行、流程是否闭环、分层是否合理 | 人工 / LLM 评审，新建或大改 skill 时打分 |

机器校验通过是**必要条件**，rubric 达标是**充分条件**——两者都过才可合并。
