# 输出规格模板 + 产出前自查清单

七维全部通过后，按本模板输出规格——这是 HANDOFF 给 `doc-generator` / `implementation-discipline` 的产物，**必须落盘成文件**（HANDOFF.md 或 PRD 草稿），不能只留在对话里。

## 规格模板

（外层用四反引号包裹——模板内含 ```accept 示例围栏，三反引号外层会被它提前闭合）

````markdown
# 需求规格 — <一句话标题>

## 问题陈述
<一句话：解决谁的什么问题，什么场景下>

## Scope（在范围内）
- ...
- ...

## Out of Scope（明确不做）
- ...
- ...

## 验收条件（可观测可测试）
- [ ] AC1: <可重复的验证步骤 + 期望输出>
- [ ] AC2: ...
- [ ] AC3: ...

## 样例对（Ground Truth）
<!-- 喂样例不喂形容词：每对 = 输入 → 期望输出。正例锚定"对的长什么样"，反例锚定
     "边界在哪"——有样例时任务从生成变插值。可命令化的样例落进下方 accept 围栏：
     围栏内每行 "<命令> :: <期望输出子串>"，spec 落盘后可被验收门禁提取为实跑考卷。
     注意：普通代码围栏（```）内的行提取器一律跳过——可提取形态只有本围栏与
     "accept: <命令> :: <期望输出子串>" 裸列表行两种。 -->
- 正例 1: <输入> → <期望输出>
- 正例 2: <输入> → <期望输出>
- 反例 1（必须拒绝 / 不得出现）: <输入> → <不得出现的输出 + 一句话理由>

可机械判定的样例（可选，能写成命令/断言就写；实例化时保留围栏形态）：
```accept
<命令> :: <期望输出子串>
```

## 约束（三分类投递）
<!-- 每条约束标注执法通道——类别决定它去哪条通道被守住（约束三分类词汇表）：
     可执行（能写成命令/断言）→ accept: 行，实跑判定；
     可命题（成不了命令，但能写成短规则 + 正反例）→ 规则与正反例锚定，留给评审对照判定；
     不可命题（品味 / 业务正确性终审）→ 显式标注人工验收，不许静默混进前两类。
     背景维度照旧四项：技术 / 资源 / 时间 / 运行环境。 -->
- 可执行: <约束> → `accept: <命令> :: <期望>`
- 可命题: <一条短规则>（正例：<...>；反例：<...>）
- 不可命题: <须人工判断的约束——如视觉风格、业务正确性终审>
- 技术：<栈 / 兼容性 / 已有系统>
- 资源：<人力 / 预算 / 外部依赖>
- 时间：<deadline 或探索性>
- 运行环境：<OS / 网络 / 权限>

## 优先级
- P0 必须：<...>
- P1 应该：<...>
- P2 可以：<...>

## 术语消歧
- "<模糊词>" = <数值 / 参考物 / 明确定义>

## 假设（需用户后续确认或修正）
- ASSUMPTION-1: <我假设 X，因为未明示>
- ASSUMPTION-2: ...

## 后续
- 直接 HANDOFF 给 doc-generator 生成 PRD
- 或作为 implementation-discipline 的输入开始编码
````

## 产出前自查清单（最后一道门）

输出规格前，逐项对照：

- [ ] 范围：能用一句话说清要解决的具体问题？（不是一段话）
- [ ] Scope：每条都是"做什么"，可执行？
- [ ] Out of Scope：至少 3 条明确"不做"？
- [ ] 验收条件：每条都能转成可重复的测试或演示步骤？（含具体输入和期望输出）
- [ ] 验收条件：没有"看起来"、"差不多"、"流畅"、"专业"等不可测词？
- [ ] 样例对：≥2 正例 + ≥1 反例，每对 = 输入→期望输出（不是形容词）？可命令化的已写成 accept: 行？
- [ ] 约束：每条标注了三分类（可执行→accept 行 / 可命题→短规则+正反例 / 不可命题→显式人工）？技术 / 资源 / 时间 / 运行环境四项背景都填了？
- [ ] 优先级：冲突取舍预先约定了？
- [ ] 术语：所有模糊量词已替换为数值或参考物？
- [ ] 假设：所有未明示但默认成立的前提，已显式写为 ASSUMPTION-<N>？
- [ ] 后续：明确指向 doc-generator（生成 PRD）还是 implementation-discipline（直接编码）？

**任一答"否"，回到对应维度继续澄清，不要放出未通过的规格。**
