# Phase L — 轻量事实核查

本文件是 research-workflow 轻量档的完整执行规范。触发场景：查数据、对比、最新进展、某个事实核实——需要多源交叉，但不出报告。量级判定见 SKILL.md「三层调研量级」表。

**不建 run_dir、不 spawn worker、不发布。** ≤20 次查询，拿到交叉验证的答案即停。

## 步骤

1. **取当前时间**：`date '+%Y-%m-%d'`，不假设。问题含"最新 / 当前 / 今年"时，把时间窗写进第一句检索。
2. **看联网能力**：agent 有内置 web_search / web_fetch 直接用；没有就走 curl 定向源（HN / GitHub / Stack Exchange / arXiv / 主流媒体直 curl）。通道状态、自检方法、按问题类型选源的命令模板见 `references/curl-sourcing.md`（那张表是特定网络环境的实测，开工前先自检）。定向源不够、已配搜索 API key 时，可走 SKILL.md「通用搜索桥接」再试一次。
3. **多源交叉（核心纪律）**：
   - ≥2 个**独立来源族**撞同一事实才写入答案。同一 URL、转载、同一厂商的多个渠道算一个族（定义见 `references/credibility-protocol.md` 第 2 节）。
   - 数字、日期、金额必须打开原文核对，不用搜索摘要里的数字。
   - 原文有限定（场景、样本、"可能"）就原样带上，不说得比原文更重。
   - 来源冲突 → 明示冲突与各自说法，不强行统一。
   - 找不到第二个独立来源 → 标「单一来源，未交叉验证」。
4. **反证一次**：对结论用反向措辞（批评 / 错误 / 更正 / 撤回）检索一次，有更正就以更正为准。
5. **输出 inline**（不落文件）：
   - 第一句给结论；
   - 关键事实，每条 ≥2 个引用（URL + 日期）；
   - 对比表（如适用）；
   - 时效标注「截至 YYYY-MM，可能已变化」。
6. **查不到就说查不到**：写「本机可用来源未查到」，给可手动验证的关键词，不编造。

## 升级到深度档的信号

出现下列任一情况，停下问用户是否转深度档（Phase 0 起步）：

- 需要 ≥5 个子问题才能回答；
- 结论要支撑一个重要决策（选型、立项、对外发布）；
- 来源之间出现实质矛盾且 20 次查询内消解不了。

## 示例

> 问：OpenAI 最新一轮融了多少？
>
> 答：截至 2026-10，最近一轮是……（金额，估值）[^1^][^2^]。两家报道的估值口径不同：A 写投后，B 写投前。
>
> [^1^]: https://… — 机构，2026-xx-xx
> [^2^]: https://… — 机构，2026-xx-xx
