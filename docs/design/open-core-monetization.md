# Open Core 商业化设计（批次三立项稿）

状态：设计稿（focus-batches §3；决策依据 docs/plans/feature-focus-2026-09.md 方向 F 与调研 dive_05——市场结构/买单人/定价锚的全部证据链在 ~/.forge/research/forge-direction-20260905-0956/dive_05.md）。本文只出设计不写代码；执行另开任务。

## 一、定位与前提

- 产品定位（调研总判断）：**跨宿主的 AI 开发证据与签核层**——治理锚在 git/PR 收口，价值锚在"证明 agent 做了什么、谁签的字、证据可否验签"。
- 商业化前提（调研 dive_05 结论）：
  1. 治理付费唯一确定增长的机构口径是 Gartner securing AI（2026 ~$2.84B → 2027 $4.8B，+68.7%）；coding 工具市场口径打架（$3.0-3.5B 窄 vs $7.65B 宽），引用必须注明。
  2. 买单人已成型：CISO/安全（审计师问句已成文——"Which reviewer approved this change, on what basis?"）与平台工程/工程效率（CodeRabbit/Greptile/Qodo 的实际买家）。
  3. 个人开发者为治理付费无先例（治理对个人是负效用）——个人线只做分发漏斗，零收费。
  4. "合规驱动购买"的时间表风险：EU 高风险义务延期至 2027-12 且 coding agent 非高风险类目——欧美叙事只能用"取证/降险/问卷通关"，禁用"强制"话术。

## 二、付费墙边界（open core）

**核心永不开收费**（Apache-2.0 承诺不破坏）：

- 策略引擎与全部任务门禁（task gates / cheat-scan / held-out / self-report / gate push）
- 本地 checklog 签名审计与验签
- forge eval 双轨自评测
- 全部 12 宿主适配与 hooks 接线
- OTel 导出器（开放格式导出是生态卡位，封闭它等于放弃标准位置）

**付费墙内**（企业价值 = 组织规模下的治理与合规）：

| 能力 | 对应调研证据 | 付费形态 |
|---|---|---|
| SSO/SAML + RBAC（组织成员与角色） | CodeRabbit 高档定价锚（$48/dev/mo 含 SSO+audit） | 席位功能 |
| 审计导出与留存合规（auditor-grade evidence：OTLP/SOC2/AAT 格式包、保留策略、法务持有） | Drata "auditor-grade evidence" 话术；IETF AAT mapper | 席位功能 + 用量超额 |
| fleet 多宿主管理（组织级策略下发、12 宿主版本对账、doctor 批量） | CSA 92% 企业缺 agent 可见性 | 席位功能 |
| 合规报告模板（信通院 16 能力项 × Forge 证据对照、SOC2/EU AI Act/ISO 42001 问卷应答包） | 信通院评估是投标门票；ISO 42001 采购问卷 | 席位功能 |
| 私有化部署包与支持 SLA | 中国 63% 市场私有化；欧美 self-host 需求 | 年度订阅 + 实施费 |

## 三、定价（对齐行业收敛形态：席位主单元 + 用量超额辅助）

- 主计费单元 = **被治理的活跃开发者席位**（governed dev/mo）：锚区间 **$20-40**（对标 CodeRabbit $24 / Greptile $30 / Qodo 折合 $15-38）。启动价建议 $25，年度 $20。
- 辅助单元 = 审计/门禁事件用量超额（对齐 Qodo $0.012/credit 池化）：免费档含每席位月度 X 万审计行导出，超出按行池计费。**"门禁通过数"不作主单元**（惩罚使用、无法比价——调研 dive_05 裁决）。
- 私有化 = 年度订阅 + 实施费（中国参照：徽商银行 52 万/年级别的私有化订阅；欧美 self-host 档另定）。
- 免费/开源档 = 全部核心功能无限制 + 组织级功能 30 天试用（漏斗转化点在"团队规模 >5 且有审计诉求"）。

## 四、GTM 顺序

1. **欧美/全球企业合规（主战场）**：模型中立 × 12 宿主是结构性差异（Anthropic 封锁第三方 harness 后"不被单一模型商锁定"无人能抄）；入口内容 = 反作弊证据链（NIST CAISI/SpecBench 学术背书）+ 审计师问句应答（CodeRabbit 治理指南同类内容打法）。
2. **个人/社区（纯漏斗）**：npm 装机量 → 平台工程选型的 de facto 标准（CodeRabbit bootstrap→$3M ARR 的自下而上路径；但 Forge 的自下而上止于"平台工程选型"，不到个人信用卡）。
3. **中国合规市场（期权式，不做直销支柱）**：池子小（IDC 2025 中国 AI 编程 ¥3.99 亿≈$55M）门票贵（信通院认证+私有化+本地法人）；路径 = 国产宿主（Kimi/CodeBuddy/ZCode）绑定的"可信放大器"+ 本地集成商授权合作（接受强势厂商白嫖核心，只对审计合规包+支持收费）。不按"渗透率 30%→91% 补涨"做收入模型。

## 五、里程碑（T0 = 立项）

| 期 | 内容 | 度量 |
|---|---|---|
| T0-T1（准备期） | 商业主体与计费基建选型（席位计量 = governed dev 识别：组织内活跃 forge 节点数）；付费能力开关与 license 文件机制；EULA/隐私政策（审计数据不出本地的承诺写进合同） | 能对 5 家设计伙伴跑通"付费墙内功能"演示 |

| T2-T3（GA） | SSO/RBAC + 合规报告模板 GA；定价 A/B（$25 vs $35） | 首批 20 付费席位；净收入留存信号 |
| T3+（中国期权） | 信通院评估启动（若做）+ 本地集成商 1-2 家 | 授权收入 ≥ 1 单（验证通道，不设增长目标） |

## 六、风险与对冲

1. **平台原生化挤压**（最大风险，长期）：付费墙内能力（SSO/审计导出）可能被宿主厂商免费化——对冲：季度"留白清单"审计（dive_01 窗口表）+ 深水资产（跨宿主统一、签名链、验签）不可被单厂商复制的部分加大投入。
2. **开源商业化历史风险**：license-flip 失去贡献者（Redis→Valkey 教训）——Apache-2.0 不翻，core/enterprise 代码物理分仓（enterprise 闭源仓，core 永远完整可用）。
3. **Gartner MQ 不作为早期里程碑**（Orosz 批评 + Anthropic 不付费不在榜的失真）——内容营销走审计师/学术背书通道。
4. **度量反噬（Goodhart）**：销售指标不得回流污染产品门禁（评分封顶的同款纪律）；"governed dev 数"定义钉死在文档，防口径漂移。
