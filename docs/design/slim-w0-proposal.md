# W0 Proposal：档位 + 预算门 + 数据面，而不是直接删 hook

## 提案

不做「凭感觉删 hook」，先立三件基础设施：档位（用户自选重量）、耗时预算硬门
（重量回归可见）、死检查报告（减法有数据）。三者全部可在现有行为（standard
档）零变化下合入。

## 备选取舍

- **直接删减默认接线**：无数据支撑的删除违反 W0 宪法「瘦身由数据决定」；且
  默认翻转让现网用户行为突变——改为 lite 可显式启用，默认切换绑定 W0.1 + W2
  双证据（已登记触发条件）。
- **只做运行时门不做接线过滤**：插件渠道可覆盖，但 forge init 渠道的 spawn
  次数降不下来——两层都要（接线过滤减条目、运行时门兜插件渠道）。
- **hook 内自检 profile（每个脚本第一行查档）**：bash 侧实现分散且难单测；
  收敛到 hookdispatch 单一咽喉 + Go 侧 spec 过滤两个点。
- **batch 单入口分派立即全量上线**：claude additionalContext 合并语义与全部
  镜像测试迁移需要独立批次的谨慎设计——本批先落其验收工具（耗时预算硬门），
  分派本体登记后续任务。

## 验收判据（事前声明）

档位生效且 standard 行为零变化（镜像/棘轮测试不改期望值即绿）；耗时预算门在
CI 常驻（首跑实测 mean 102ms 入档）；死检查报告三态判定有单测、输出带诚实
边界；compat 快照增量全部可归因。
