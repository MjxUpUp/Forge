# research-workflow 复盘（2026-10）

日期：2026-10-15 ｜ 状态：行动已落地（见「落地状态」） ｜ 明细：[证据附录](2026-10-research-workflow-review-evidence.md)
范围：本机全部 23 个调研 run（`~/.forge/research/` 10 个、`~/.research-workflow/` 13 个）、`docs/surveys/` 落库调研、10 月 11 次调研会话转录；外部调研覆盖学界 64 条引用与业界产品 / 开源 / 社区 skill。方法：逐 run 6 项打分、31 条承重断言回原文核验、转录取证。

## 结论

1. **没有编造来源，主要的失真方式是转述时把话说重了。** 31 条承重断言回原文核验：完全支持 21 条（68%），部分支持 7 条（23%），不支持 3 条（10%），死链和捏造都是 0。失真都出在 dive → report → 设计文档这条转述链上，有三种：
   - 删掉原文的 hedge："perhaps" 被写成"反升 43 倍"；
   - 丢掉场景限定："仅 ChatDev"没了；
   - 两篇论文拼成一个新结论。

   学界的定位与此一致：deep research 终稿错误有 84.7% 来自编排 / 写作层（arXiv 2608.24306）。
2. **"高信度"大量是循环互证。** 信度按几个 worker 撞到同一事实来计，没按几个独立来源计。同一 URL、转载、共作者论文、本机旧报告都被当成独立源。agent-memory 的 17 条高信度里有 12 条只有单一来源。
3. **质量门都靠自查。** 质疑、互证分级、出口条件，全是写报告的那个 agent 按散文规则检查自己，既没有确定性脚本，也没有隔离上下文的核验者。结果是流程被静默降级：完整撒网 1/23，9 月没有一个 run 做过矛盾消解，rsi-selfevolve 跳过互证却支撑了两项功能决策。
4. **偏题主要有两种。**
   - 答了相邻问题：用户问"是不是真需求"，报告论证的是"问题存在"。
   - 把外部结论直接当成本地可做：两条标着"✅ 已证明、现在就可以做"的建议，用本机记录一查就被推翻了。
5. **工程面比较脆。**
   - Phase L 一次都没用过，飞书只发布了 2/23。
   - agent 把建目录命令改写成 `RUN=…-$(date …); mkdir -p $RUN` 后会被 hazard-guard 拦下（10-10、10-13 各一次；SKILL.md 原文的字面写法本身不拦），未确认的拦截按项目计，会卡住同项目所有 task complete。
   - 报告自报的搜索量比实测高 23–60%。
   - 设计文档引用的 2 个 run 目录已经不存在。
   - 下游文档基本没有保留信度标注。

做得好的：0 捏造、0 死链，2026 年的新事件都追到了一手页面。业界同类 agent 的引用 URL 中有 3–13% 是捏造的（arXiv 2604.03173）。另外，10 月起信度标注普及，也开始出现跨 run 自我纠错，例如主动更正了 ECE 0.144。

**根因有四个：**
- 关键门只有散文规则，没有可执行检查；
- 信度的计数单位错了，数的是 worker 不是独立来源；
- 流程优化的是搜索量，而不是"把问题答完"；
- 转述链上没有任何字段要求限定条件跟着断言一起往下传。

## 行动

原则沿用 Forge 的分层：能脚本化的改成确定性检查；不能脚本化的交给隔离上下文的独立执行者；散文规则只留给判断题。每条行动在附录第四节有展开。
